About
I build backend systems — the part between a request hitting a server and a row landing in a database, correctly, under load, and in a way the next engineer can follow.
Four years into a Computer Engineering degree, that interest has turned into three backend internships and a few full-stack projects where the backend is the actual subject, not a REST wrapper around a frontend idea. I'd rather read a query execution plan than tune a modal's animation curve — that's the trade I chose, deliberately.
Most recently: cut integration bugs ~25% by tightening request validation and error contracts, and cut endpoint latency ~30% through indexing and caching — the kind of work that doesn't demo well but is most of the job.
<br/>
Currently Focused On
Backend architecture in Spring Boot and FastAPI — layered, testable, boring in the right ways
Query optimization and schema design across relational and document stores
Systems that stay correct under load, not just correct in a demo
Reading into distributed systems and infrastructure fundamentals beyond a single service

Engineering Philosophy
Measure before optimizing — profiling beats guessing, every time
A schema is a decision you'll live with; make it deliberately
Write code for the engineer who reads it next, not the one writing it now
Simplicity is a feature; cleverness is a liability until proven otherwise
Reliability isn't the exciting part of the system — it's the point of it
